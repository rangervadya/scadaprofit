# Аудит изменений 4.3.5

## Подтверждённая причина нулевого списка соединений в 4.3.4

В `_build_join_candidates()` версии 4.3.4 входные рёбра предварительно фильтровались только по `component_role == 'line_structure'`. Также оба отрезка должны были иметь длину не менее 25 px, зазор должен был быть 7–28 px, боковое отклонение — не более 4,5 px, а совпадение касательных — не хуже `-0.94`. Поэтому короткие фрагменты и концы из `ambiguous` не попадали в диагностический список, даже если локальная геометрия выглядела согласованной.

## Изменение 4.3.5

- Диагностические предложения строятся по открытым окончаниям `line_structure` и `ambiguous` компонентов.
- Короткие фрагменты от 8 px рассматриваются, если у них есть пригодная локальная касательная.
- Диапазон предложения: 4,5–45 px; максимальное боковое отклонение 8 px; минимальное направление обоих концов 0,82; взаимная касательная не хуже -0,85.
- Текстовые/аннотационные компоненты исключены.
- OCR overlap, короткая длина, близость к границе листа и альтернативные пары помечаются в `review_flags`.
- Кандидаты высокого приоритета — лишь оценка геометрии и чернил, не вероятность и не автоматическое разрешение на соединение.
- Никакая связь не меняет исходный граф автоматически. Пользователь сам нажимает «Добавить»; конкурирующие варианты для использованных концов затем удаляются из списка.

## Валидация

`npm run check`: синтаксис Node.js, компиляция Python и полный набор unit-тестов прошли успешно. Автоматическая проверка Docker-сборки и контроль на исходном пользовательском изображении в локальной среде недоступны; после обновления необходим контрольный повторный запуск на том же чертеже.
