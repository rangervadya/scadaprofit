# ScadaProfit 4.5.0 — краткая инструкция по запуску и работе

## 1. Обновление

В каталоге проекта:

```bash
docker compose build app
docker compose up -d --no-deps app
docker compose restart gateway
```

При первом развёртывании:

```bash
docker compose up -d --build
```

Не удаляй постоянный том `cad_jobs`: в нём хранятся аккаунты, задания, отчёты и CAD-проекты.

## 2. Первый вход и настоящая авторизация

При самой первой настройке создаётся единственный аккаунт разработчика: имя, логин и пароль. После этого открывается обычная форма входа только с полями «Логин» и «Пароль». Сервер находит аккаунт по логину и проверяет введённый пароль по сохранённому криптографическому хешу. Нельзя выбрать пользователя или роль из списка и войти без пароля. Неверная пара логин/пароль отклоняется.

## 3. Создание аккаунтов руководителями

Разработчик создаёт двух руководителей и, при необходимости, начальные аккаунты приёмщиков и слесарей. Далее каждый руководитель входит под личным логином и паролем, открывает «Создать аккаунты», вводит имя сотрудника и выбирает роль «Слесарь» или «Приёмщик». Сервер автоматически генерирует уникальный логин и случайный пароль. Эти данные показываются один раз после создания — скопируй и передай сотруднику безопасным способом. Руководитель не может создавать других руководителей или разработчиков. Лимит — два активных аккаунта руководителя.

## 4. Рабочий процесс слесаря

Руководитель открывает «План работ», выбирает дату, улицу, дом, слесаря и инструкции. Назначение появляется только в личном кабинете выбранного слесаря.

Слесарь выполняет последовательность кнопками:

1. «Начать обход дома».
2. «Отметить: прошёл этот дом».
3. «Отметить: пришёл в офис».
4. Прикрепить **только изображение ручного эскиза**, нарисованного от руки на бумаге, и отправить его.

Фотографии самого дома/объекта не прикрепляются и не требуются. GPS, координаты, карты и фоновое отслеживание отсутствуют. Руководитель видит только отметки кнопок и время их нажатия.

## 5. Уведомление, CAD и заключение

После отправки ручной схемы сервер сохраняет оригинал и ставит задачу в штатную очередь автоматической CAD-реконструкции. Схема привязывается к улице и дому. После обработки приёмщик получает уведомление в меню «Уведомления» с адресом.

Приёмщик открывает уведомление, видит исходный ручной эскиз и предпросмотр преобразованной векторной CAD-схемы. По кнопке можно открыть схему в CAD-редакторе, проверить результат и включить/выключить оригинальную подложку. Затем приёмщик нажимает «Перенести схему в заключение». Она появляется в разделе «Заключение» как карточка с адресом, CAD-предпросмотром и ссылками на SVG/DXF и CAD-редактор.

## 6. Роли

- **Слесарь:** видит только назначенные ему задания, ставит отметки и отправляет ручные эскизы.
- **Приёмщик:** получает уведомления, открывает CAD-результаты и переносит их в заключение, принимает или возвращает работу.
- **Руководитель (до двух аккаунтов):** назначает работы, видит отметки команды и создаёт аккаунты слесарей/приёмщиков.
- **Разработчик:** полный доступ, управление и тестирование всех ролей и модулей.

## 7. Проверки и ограничения

Локальные проверки исходников:

```bash
npm run check
```

Для полевого доступа через интернет настрой HTTPS и `COOKIE_SECURE=1` в `.env`. GPS-разрешение не требуется. Полный Docker-запуск следует проверять на целевом сервере, где доступен Docker и установлены внешние OCR/AI зависимости.
