# ScadaProfit 4.3.18 — восстановление геометрии и профиль эталонного листа

## Что изменено

1. **Портретный лист A4.** Чистовой SVG/DXF/PDF теперь используют страницу 210×297 мм с вертикальным viewBox 850×1200, соответствующим загруженному изображению 648×918 px.
2. **Привязка шаблона к заданию.** Сервер передаёт сохранённый эталон в `processor.py --template` и закрепляет его копию внутри папки задания. Повторный запуск использует тот же файл, даже если глобальный эталон впоследствии заменят.
3. **Без дублирования заполненного JPEG.** При загрузке JPEG читаются его размер и ориентация. Пиксели заполненного скана не вставляются фоном, иначе исходные трубы и надписи появились бы второй раз.
4. **Сохранение координат.** Чистовая компоновка отображает весь исходный лист целиком, сохраняет относительное расположение верхней сети и нижних стояков и не выпрямляет автоматически линии.
5. **Разделение слоёв.** Primary-пути остаются в `PIPE_MAIN`; неотобранные фрагменты переводятся в `DETAIL_REVIEW`. Сомнительные OCR-тексты не попадают в чистовой слой; primary числовые обозначения сохраняют исходную позицию.
6. **OCR budget.** Базовый бюджет повторов Qwen для каждой плитки установлен в 0. Успешные плитки остаются в checkpoint, неуспешные повторяются при следующем запуске. Построчный OCR блоков не расходует время, если основная сетка OCR не завершена.
7. **Трассировка и статус.** Qwen PIPE не запускается до полного OCR. Время задания в compose увеличено с 45 до 90 минут, чтобы последовательные сетки OCR 3×3 и PIPE 3×3 имели достаточный временной бюджет.
8. **Защита от частичной выдачи.** При `complete: false` SVG/DXF/PDF заблокированы в интерфейсе; JSON остаётся доступен для диагностики. Частичные SVG/DXF маркируются «НЕПОЛНЫЙ РЕЗУЛЬТАТ — ТОЛЬКО ПРОВЕРКА».
9. Количество CAD-путей в интерфейсе называется числом геометрических кандидатов; оно не интерпретируется как число полностью проверенных трубопроводов.

## Важное ограничение загруженного эталона

Приложенный JPEG — это заполненный скан чертежа, а не пустой бланк. В этой версии по нему восстановлены профиль A4 portrait и базовые заголовки/подписи легенды. Растровая подложка не используется. Точная векторизация пиктограмм легенды, автоматическое распознавание адресных полей и перенос фактических подписей исполнителей пока не реализованы. Поэтому это корректная основа для проверки компоновки, но ещё не подтверждение пиксель-в-пиксель идентичности шаблону.

## Обновление через GitHub и Docker

Заменить файлы, сохраняя пути: `processor.py`, `server.js`, `package.json`, `compose.yaml`, `drawing_template.py`, `clean_layout.py`, `clean_export.py`, `pipeline_diagnostics.py`, `public/app.js`, `public/index.html`, `tests/test_engine.py`, `CHANGELOG-RU.md` и этот файл инструкции.

Не загружать ZIP целиком в корень GitHub-репозитория. Не удалять Docker-том `cad_jobs` и папку `DATA`: в них находятся адресная библиотека, исходники заданий и checkpoint.

На сервере из корня проекта выполнить:

```bash
git pull --ff-only origin main
sudo docker compose config --quiet
sudo docker compose build app
sudo docker compose up -d --no-deps app
sudo docker compose ps
curl -sS http://127.0.0.1:3001/api/health
```

После обновления открой раздел **«Шаблон оформления»**, выбери приложенный файл `cad-reference-sheet-a4-portrait.jpg` и нажми **«Сохранить шаблон»**. Он будет сохранён в постоянном хранилище `cad_jobs`; новая версия закрепит копию эталона в папке задания при следующем запуске. Этот JPEG — заполненный образец, поэтому он задаёт профиль A4 portrait и тексты шапки/легенды, но не используется как растровая подложка.

В `/api/health` ожидается `"version":"4.3.18"`, `pythonJobTimeoutMs: 5400000` и `qwenLimits.tileRetryBudget: 0`. Перезапускается только приложение `app`; Ollama, Qwen, VDGO, PostgreSQL и Gateway не требуется пересобирать. Не выполнять `docker compose down -v`.

## Повтор проблемной схемы

Открой ту же схему в адресной библиотеке и нажми **«Повторить преобразование»** / **«Продолжить обработку»**. Не создавай новое задание повторной загрузкой той же фотографии: новый ID не увидит старые checkpoint. В журнале ожидаются `restored from checkpoint` для успешно распознанных плиток и повторный запуск только недостающих OCR/PIPE плиток.

Результат с `complete: false` остаётся частичным. После `complete: true` всё равно проверь соединения, повороты, диаметры, нумерацию и подписи по исходному скану. Вычислительное завершение не является инженерным утверждением о правильности схемы.
