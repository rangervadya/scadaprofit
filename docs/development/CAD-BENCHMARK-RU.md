# Контрольный прогон ScadaProfit

Рабочий режим использует прежние настройки Qwen и пиксельные координаты.
Варианты проверки запускаются по одному, каждый пишет результат в новый каталог.
Схемы заказчика и результаты прогона храните локально.

## Подготовка на сервере

Из каталога проекта установите PyMuPDF в отдельное окружение. В каталоге
должны быть `Scada` и `cad-pilot` из комплекта.

```bash
python3 -m venv /tmp/scada-benchmark-venv
/tmp/scada-benchmark-venv/bin/pip install pymupdf
/tmp/scada-benchmark-venv/bin/python cad-pilot/prepare_benchmark.py ./cad-pilot/benchmark
```

Скрипт извлекает 89 страниц с эскизами из PDF. Разбиение по адресам даёт
68 листов для подбора и 21 для контроля. JPG остаются доступными как
визуальные образцы. Для расчёта метрик нужна проверенная вручную разметка
в координатах `prepared-input.png`.

## Сравнение вариантов

Используйте контейнер приложения с обычными настройками и запущенный Ollama.
При замерах выбирайте время без параллельных заданий распознавания.

```bash
docker compose run --rm --no-deps \
  -v "$PWD/cad-pilot/benchmark:/benchmark" app \
  python /app/backend/engine/evaluate_examples.py /benchmark/manifest.json /benchmark/baseline
```

Повторите команду с новым выходным каталогом и одним параметром
`--variant ocr-normalized`, `--variant pipe-normalized`, `--variant keep-alive`,
`--variant batch`, `--variant threads`, `--variant clahe` или `--variant bilateral`.
Для подбора используйте `--split train`. CLAHE и bilateral применяются к
нормализованному серому каналу OpenCV и Tesseract. Дополнительный OCR рукописных
блоков Qwen сохраняет прежнюю систему координат.

В параллельном терминале запишите пиковую VRAM на хосте и проверьте
размещение модели внутри контейнера Ollama.

```bash
nvidia-smi --query-gpu=timestamp,memory.used --format=csv -l 1
docker compose exec ollama ollama ps
```

Сравните `report.json` по времени `total_through_final_dxf`, числу запросов,
`truncated_responses`, времени загрузки модели и числу отклонённых координат.
Чтобы сравнить холодные пуски, каждый вариант должен начинаться при
одинаковом состоянии модели. Для сравнения качества включайте один
эксперимент за раз.

## Разметка

В записи `manifest.json` добавьте `reference` с путём к проверенному JSON
относительно манифеста. JSON использует `image.width`, `image.height` и
`documentModel` с массивами `nodes`, `pipes`, `labels`, `symbols`.
За основу можно взять структуру `graph.json` и сверить каждый объект с
эскизом и эталоном. В эталоне перечисляйте только подтверждённые объекты.
Для символов укажите тип в `kind`, для подписей — `bbox`, `text` и
`targetId` узла, трубы или символа, если назначение подтверждено.

Эвалюатор считает CER/WER, совпадение штрихов на растре, совпадение узлов и
связей, классификацию символов и привязки подписей. Узлы и центры боксов
сопоставляются по ближайшей позиции в пределах 8 пикселей. Проверку
графа проводите вместе с визуальной сверкой. Для схем без разметки
отчёт содержит измерения времени и диагностику распознавания.

Подключение PP-OCRv6, замена квантизации, удаление адаптеров и включение
экспериментальных режимов в рабочей конфигурации требуют результатов
прогона на контрольных схемах.
