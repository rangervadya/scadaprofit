# ScadaProfit 4.5.17 — схемы, выезды, CAD и технические заключения

ScadaProfit объединяет распознавание ручных схем, редактируемый CAD, планирование выездов, приёмку отчётов и подготовку технических заключений.

## Рабочий процесс

1. Слесарь входит по личному логину и паролю и видит назначения по датам и адресам.
2. Обход отмечается только кнопками «Начать обход», «Прошёл дом», «Пришёл в офис». GPS, координаты и фоновое слежение не используются.
3. Слесарь отправляет ручной эскиз и фотографии дефектов отдельными типами отчётов.
4. В меню приёмщика «Уведомления» каждый назначенный дом отображается одной папкой. В ней вместе находятся все схемы и комплекты фотографий дефектов, отправленные по этому заданию.
5. Приёмщик отдельно проверяет каждый материал. Схему можно открыть в CAD, исправить и сохранить; фотографии дефектов можно принять или вернуть.
6. После проверки всех материалов приёмщик нажимает одну кнопку «Добавить всю папку в заключение». Схемы попадают в пункт 7, фотографии дефектов — в Приложение 3. Непроверенные и возвращённые материалы блокируют перенос всей папки.
7. Руководители и приёмщики распределяют улицы и дома слесарям. Руководители создают учётные записи; разработчик имеет полный доступ.

## Структура репозитория

- `frontend/` — единственное React SPA для всех ролей и рабочих разделов; отдельной папки/контейнера frontend ВДГО нет.
- `services/ollama/api/` — Node.js API и workforce-модуль.
- `services/ollama/engine/` — Python-движок распознавания и CAD.
- `services/vdgo/` — отдельный API и генератор PDF/Word технических заключений.
- `infra/` — Dockerfile, Nginx, Compose-override и скрипты установки.
- `tests/` — проверки Node.js, Python и VDGO.
- `docs/` — инструкции и техническая документация.

## Запуск

Требуются Docker Engine и Docker Compose v2. Для обработки через локальный Ollama/Qwen желателен GPU и NVIDIA Container Toolkit; без GPU приложение сохраняет доступные CPU-пути.

1. Скопируй `.env.example` в `.env` и задай уникальный `POSTGRES_PASSWORD`. Для HTTPS установи `COOKIE_SECURE=1`.
2. Из корневой папки проекта выполни:

   ```bash
   docker compose config --quiet
   docker compose up -d --build
   ```

3. Открой `http://АДРЕС-СЕРВЕРА:3001` (или порт из `WEB_PORT`). При первом входе создай аккаунт разработчика.
4. Через панель команды создай аккаунты руководителей, приёмщиков и слесарей.

## Обновление

```bash
git pull --ff-only
docker compose build --no-cache app vdgo-backend
docker compose up -d --remove-orphans --no-deps --force-recreate app vdgo-backend
docker compose restart gateway
docker compose ps
```

**Не удаляй Docker-тома** `cad_jobs`, `ollama_data`, `vdgo_output`, `vdgo_uploads` и `vdgo_postgres_data`. В них находятся схемы, отчёты, фотографии, документы и база данных.

## Единый frontend

Весь пользовательский интерфейс ScadaProfit теперь находится в одном React-приложении `frontend/src/` и собирается в `frontend/public/vdgo/`. Адрес `/` перенаправляет на `/vdgo/`. Отдельный frontend ВДГО и второй frontend-контейнер отсутствуют; API и генератор PDF/Word остаются в отдельном `vdgo-backend`.

Для локальной сборки интерфейса: `npm --prefix frontend ci && npm --prefix frontend run build`.

## Проверки

```bash
npm --prefix services/ollama run check
PYTHONPATH=services/ollama python -m unittest discover -s tests/vdgo -p 'test_*.py'
```

После обновления отдельно проверь статус контейнеров на целевом сервере: успешные тесты исходников не заменяют проверку реального Docker-развёртывания.
