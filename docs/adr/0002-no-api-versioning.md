# ADR 0002 — Без версионирования путей API

- **Статус**: принято
- **Дата**: 2026-11-14
- **Контекст**: P1-10

## Контекст

План рефакторинга предполагал `/api/v1`. Обсуждение с владельцем показало, что
версионирование путей не нужно: фронтенд и backend поставляются одним артефактом
(`compose.yaml`), внешних потребителей API нет.

## Решение

Пути остаются `/api/...` без версии. Контракт стабилизируется двумя механизмами:

1. `docs/openapi.yaml` — описание всех `/api/*` и `/vdgo/*` маршрутов.
2. `tests/node/openapi.test.js` — статическая проверка, что каждый путь из спеки
   существует как express-маршрут (`server.js` + `workforce-system.js`) или
   nginx-route (vdgo).

Единый формат ошибки:

```json
{ "error": "human readable message", "code": "MACHINE_CODE", "details": { } }
```

`error` — всегда строка (обратная совместимость с фронтом), `code` — стабильный
машинный код, `details` — опциональные детали.

## Последствия

- **Плюсы**: нет накладных расходов на версионирование, контракт проверяется в CI.
- **Минусы**: при ломающих изменениях нет «старой версии» — нужна согласованность
  фронта и бэка (они деплоятся вместе).
- **Правило**: ломающие изменения оформляются как новые поля/коды, а не как смена
  существующих; при необходимости — feature flag.
