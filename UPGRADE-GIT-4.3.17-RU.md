# ScadaProfit 4.3.17 — исправление тайм-аутов и восстановление обработки

## Что исправлено

1. **Бюджет повторных попыток отдельный для каждой плитки.** Раньше первая медленная плитка могла расходовать общий бюджет повторов этапа, из-за чего последующие получали меньше попыток.
2. **Время повтора увеличивается контролируемо.** По умолчанию следующий OCR-запрос получает до 288 секунд, PIPE — до 360 секунд; фактические значения ограничиваются настройками окружения и общим сроком задания.
3. **Учитывается общий срок задания.** Перед запуском очередной плитки код проверяет, останется ли время для OCR-постобработки и экспорта. Не начатые плитки откладываются, а не обрываются общим SIGTERM.
4. **Если OCR не завершил все плитки, дорогая трассировка Qwen откладывается.** Программа всё равно строит и экспортирует явно помеченный частичный SVG/DXF и `graph.json` по доступной геометрии. Такой результат предназначен только для проверки, не для использования как готовый чертёж.
5. **Повтор того же задания использует успешные checkpoint-файлы.** Успешные OCR/PIPE-плитки не запрашиваются повторно, если исходное изображение и параметры этапа не изменились.
6. **Частичный результат теперь открывается в интерфейсе.** Если задание завершилось неполно, но `graph.json` успел сохраниться, приложение показывает SVG/DXF-граф для проверки и кнопку «Повторить недостающие участки».
7. Интерфейс сообщает, что при повторе будут восстановлены ранее сохранённые участки.

Не заменять `compose.yaml`, `docker-compose.yml`, `nginx-unified.conf`, `.env` или конфигурацию Ollama. Не загружать ZIP целиком в корень репозитория.

## Установка через GitHub и Docker

1. Распаковать ZIP локально.
2. Заменить в GitHub пять файлов выше в ветке `main`.
3. Создать Commit changes.
4. На сервере выполнить:

```bash
cd /opt/scadaprofit
git pull --ff-only origin main
sudo docker compose config --quiet
sudo docker compose build app
sudo docker compose up -d --no-deps app
sudo docker compose ps
curl -sS http://127.0.0.1:3001/api/health
```

В health API ожидается `"version":"4.3.17"`.

`--no-deps app` пересоздаёт только приложение; Gateway, Ollama, Qwen, VDGO и PostgreSQL не нужно пересобирать или перезапускать.

## Как возобновить проблемную схему

Для задания `da8e06d2-0792-4765-973a-331f6c2fff5d` уже существуют checkpoints:

- `ocr-tile-01.json`
- `ocr-tile-03.json`
- `ocr-tile-09.json`

После установки 4.3.17 открой **то же задание** в адресной библиотеке и нажми «Повторить преобразование». Не загружай исходное фото как новую схему: новое задание получит другой ID и другую папку, поэтому не сможет использовать checkpoints старого задания.

При повторе должны появиться строки `restored from checkpoint` для плиток 1, 3 и 9. Отсутствующие OCR-плитки будут запрошены заново. Если времени не хватит на все участки, приложение сохранит частичный результат с `analysisStatus: incomplete` и `complete: false`, не запуская Qwen PIPE на неполном OCR. Такой результат теперь будет открыт в интерфейсе как неполный, с предупреждением и кнопкой продолжения. Повтори обработку того же задания ещё раз — сохранённые плитки восстановятся.

Когда все OCR-плитки завершены, последующий запуск сможет перейти к трассировке PIPE. Если часть PIPE-плиток не завершится, аналогично будут сохранены успешные PIPE checkpoints для следующего повтора.

## Важные ограничения

- Эта версия не гарантирует, что все участки завершатся за один 45-минутный запуск. Она делает длинную обработку возобновляемой и предотвращает потерю уже выполненных этапов.
- Частичный SVG/DXF — только для проверки. Для окончательного результата `graph.json` должен иметь `complete: true` и `analysisStatus: complete`.
- Qwen 4B, разрешение исходника, сетка 3×3 и последовательная работа модели не сокращались.
- Настройки других контейнеров и Docker-тома не изменяются.
