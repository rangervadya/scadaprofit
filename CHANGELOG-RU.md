## 4.2.8

- Исправлена логика клиентского SVG/DXF: наличие массива Qwen `semanticRoutes` больше не отключает OpenCV-рёбра с `cad_include=true` в основном слое.
- `PIPE_MAIN` строится по выбранным геометрическим путям OpenCV, явным включениям пользователя и ручным соединениям.
- Семантические маршруты Qwen перенесены в отдельный замороженный слой DXF `QWEN_REVIEW`.
- Неотобранные сегменты OpenCV остаются на замороженном `DETAIL_REVIEW`.
- Исправлены подписи и статус интерфейса; отображается раздельное количество основных CAD-путей и подсказок Qwen.
- Backend/frontend/package version синхронизированы на 4.2.8.

## 4.2.7

- Для OCR и трассировки труб вместо общего `format: "json"` передаются отдельные JSON Schema через Ollama `format`: OCR обязан возвращать массив `annotations`, а трассировка — массив `routes` с координатами.
- Трассировка упрощена для небольшой vision-модели: теперь Qwen ищет отдельные прямые участки труб с двумя концами, а не пытается сразу описать сложную полилинию всей сети. Повороты и Т-ответвления возвращаются как набор видимых отрезков; стыковка остаётся задачей CAD-графа.
- OCR-лимит увеличен с 1024 до 2048 токенов на плитку, потому что в диагностике 4.2.6 все четыре ответа завершались `done_reason=length`.
- Лимит трассировки по умолчанию увеличен до 2048 токенов; максимум 24 отдельных отрезка на плитку.
- Диагностика отмечает усечённые ответы (`truncated` / `truncated_tiles`).
- Добавлены проверки, что формат JSON Schema и новые бюджеты токенов действительно передаются в Ollama.
- 34 автоматических теста проходят локально. Реальное распознавание конкретной схемы на сервере должно быть проверено после обновления.

## 4.2.6

- Семантическая трассировка труб теперь выполняется по перекрывающимся фрагментам 2×2, а не одним запросом по всему листу.
- Каждый фрагмент обрабатывается с контекстным перекрытием, а в экспорт попадает только его неперекрывающаяся центральная область: это предотвращает двойные линии на стыках.
- Добавлена обратная привязка координат каждого фрагмента к исходному листу и обрезка полилиний по границам областей.
- Диагностика `graph.json` теперь содержит по каждой OCR/semantic-плитке JSON-ключи ответа, `done_reason`, число входных/выходных токенов, количество исходных и принятых объектов. Текст ответа не сохраняется.
- OCR принимает несколько распространённых названий массива и поля текста (`annotations`, `texts`, `text_regions`, `labels`, `objects`, `items`, а также `text`/`value`/`label`/`content`).
- При успешном ответе без распознанных надписей статус явно показывает `empty_result`, а не маскирует это под недоступность модели.

## 4.2.3
- Перестроен основной CAD-экспорт: Qwen3-VL выделяет семантические осевые маршруты труб, а не используется только как OCR поверх пиксельной трассировки.
- Добавлена отдельная структурированная задача Qwen для маршрутов, углов и ответвлений с исключением рукописных цифр, размерных линий, выносок, стрелок и символов.
- OCR переведён на четыре перекрывающихся увеличенных фрагмента; рамки умеренно уверенных распознаваний тоже исключают буквы/цифры из геометрического канала.
- Когда семантические маршруты доступны, SVG/DXF использует их на `PIPE_MAIN`; OpenCV-кандидаты остаются на замороженном `DETAIL_REVIEW`.
- Если Qwen не вернул маршруты, слой PIPE_MAIN остаётся пустым, а пиксельные кандидаты доступны только в DETAIL_REVIEW и исходном оверлее.
- 23 автоматических теста: масштабирование OCR-фрагментов, подавление штрихов низкоуверенного текста, масштабирование Qwen-маршрутов и приоритет семантических полилиний в экспорте.
