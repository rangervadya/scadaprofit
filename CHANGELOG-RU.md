# Изменения 4.3.18

## Геометрия и компоновка листа
- Чистовая компоновка перешла на профиль A4 portrait, соответствующий приложенному примеру (648×918 px). Для растрового эталона считываются формат, размеры и ориентация; заполненный JPEG не вставляется как подложка, чтобы не дублировать линии и подписи.
- Геометрия переносится из исходной системы координат на всю страницу с сохранением пропорций. Автоматическое выпрямление и схлопывание близких координат в чистовом экспортёре отключено.
- Неподтверждённые трубные фрагменты сохраняются отдельно в `DETAIL_REVIEW`; в `PIPE_MAIN` попадают только primary-пути.
- В чистовой слой допускаются только primary числовые подписи. Непроверенные слова и сомнительные OCR-значения остаются в диагностическом графе.

## OCR, трассировка и безопасность экспорта
- Бюджет повторных попыток плитки по умолчанию — 0. Ошибочная плитка повторяется при следующем запуске, успешные OCR/PIPE плитки восстанавливаются из checkpoint. Это не позволяет первой медленной плитке расходовать десятки минут на экспоненциальные повторы.
- Построчный OCR рукописных блоков откладывается, пока не завершены все основные OCR-плитки. Qwen-трассировка труб по-прежнему не запускается по неполной карте OCR.
- Лимит задания увеличен до 90 минут для последовательного OCR 3×3 и PIPE 3×3 с резервом времени на построение и экспорт графа. Лимит остаётся настраиваемым через `PYTHON_JOB_TIMEOUT_MS`.
- Частичная геометрия помечается watermark в SVG/DXF; интерфейс блокирует SVG/DXF/PDF до окончания всех плиток, оставляя JSON для диагностики и кнопку продолжения.
- Статистика переименована: количество CAD-путей — это число геометрических кандидатов, а не подтверждённые трубопроводы. Завершение вычислительных этапов не снимает `needs_review` и не заменяет инженерную проверку.

## Шаблон
- Сервер прикладывает сохранённый JPEG к запуску Python через `--template` и фиксирует копию эталона в папке задания, чтобы повтор использовал тот же профиль.
- Эталон из текущей загрузки — заполненный скан, а не чистый бланк. Его размеры/ориентация используются как профиль страницы; точные легендарные пиктограммы, индивидуальные поля адреса и подписи пока не векторизуются автоматически.

## Проверки
- `npm run check` — успешно.
- JavaScript и Python syntax checks — успешно.
- Unit tests: **118 passed**.
- Проверены рендеры A4 portrait, сохранение координат, слой `DETAIL_REVIEW`, фильтрация numeric labels watermark неполного SVG/DXF и блокировка диагностики для незавершённого OCR.
- Реальный прогон Qwen/Ollama и Docker GPU на целевом сервере в этой среде не выполнялись.

# Изменения 4.3.7

## Классификация трубопроводной геометрии
- Добавлен отбор крупных связных многоветвевых компонентов с узлами степени до 8. Критерий учитывает количество рёбер/ветвей, суммарную длину, плотность, повороты, среднюю поддержку исходными чернилами и OCR-перекрытие.
- Исправлен конфликт, при котором общий `dense_symbol_cluster` мог отменять независимые положительные признаки связного или углового маршрута. Исключение ограничено компонентами с достаточной топологией и низкими OCR/turn metrics.
- Изолированные линии и компоненты с сильным OCR-перекрытием не продвигаются в основной слой только на основании чёрных пикселей.

## Диагностика
- В `graph.json` добавлены `mean_ink_support`, `max_edge_ocr_overlap`, `short_edge_ratio` и `topology_network_candidate`.
- В `summary` добавлены количества кандидатов сетевой топологии и их рёбер, отобранных в `PIPE_MAIN`.
- В статус интерфейса выведена статистика структурных компонентов и сетевых кандидатов.

## Безопасность геометрии
- Кандидаты соединений и пересечения остаются review-only; автосоединение не расширялось.
- Все экспортированные маршруты необходимо сверять с исходным инженерным чертежом.

## Проверки
- 63 unit-теста пройдены.
- Проверены синтаксис Python и JavaScript.
- Docker-сборка на целевом сервере не выполнялась в этой среде.
