# ScadaProfit 4.3.21

## OCR при сбоях отдельных Qwen-плиток
- Если отдельная OCR-плитка Qwen завершилась ошибкой, приложение запускает ограниченный по времени Tesseract только на этой плитке. Найденные надписи сохраняются с координатами в исходном изображении и диагностикой резервного прохода.
- Резервные надписи всегда остаются неподтверждёнными и требуют проверки оператором. Они не считаются успешной обработкой Qwen, не снимают статус неполного OCR и не разрешают экспорт незавершённой схемы.
- Основное распознавание Qwen имеет приоритет при совпадающих областях; резервный текст не заменяет штатную расшифровку.

## Исправление ориентации документа
- Если Tesseract OSD не достигает порогов уверенности, выполняется дополнительная OCR-оценка четырёх поворотов страницы (0/90/180/270 градусов).
- Автоповорот принимается только при достижении минимальной оценки и достаточного отрыва от второй ориентации. При неоднозначности остаётся исходная ориентация.
- В диагностику подготовки изображения добавлены оценки каждой ориентации, число распознанных токенов, порог преимущества и причина решения.

## Автоматический черновик → Ручной CAD
- Добавлен API `/api/manual-cad/import-job/:jobId` и кнопка переноса из результата автоматической обработки в отдельный проект Manual CAD.
- Подложкой служит `prepared-input.png` — та же ориентация и система координат, в которой построен граф. Несовпадающий исходный JPEG не подставляется.
- Переносятся только primary CAD-линии и явно подтверждённые вручную соединения. Review-линии не повышаются до подтверждённых труб; пересечения сами по себе не создают узлы.
- OCR-подписи сохраняются как редактируемый текст с обязательной проверкой. Символы импортируются только при наличии явного поддерживаемого типа. Неподтверждённые числовые значения не превращаются в размерные линии.
- Автоматически импортированный проект помечается как черновик и содержит предупреждения; при незавершённой обработке это явно указано в заметках.

## Улицы и дома / граница изменений
- Существующая адресная библиотека и сценарий загрузки фотографий по улицам/домам сохранены. Хранилище `address-library.json` не менялось. Отдельная база заказчика в архиве проекта отсутствует, поэтому новые подключения к БД не создавались.

## Проверки

# ScadaProfit 4.3.20

## Новый отдельный модуль «Ручной CAD»
- Добавлена отдельная страница `/manual-cad.html`, открываемая из основного CAD-приложения.
- Реализовано создание и серверное сохранение нескольких ручных проектов в `DATA_DIR/.private/manual-cad`; проекты и подложки не смешиваются с автоматическими заданиями.
- Добавлена загрузка исходного изображения JPG/PNG/WEBP/TIFF до 18 МБ как временной подложки для ручной векторизации. Подложка отображается в редакторе, но не вставляется в чистовой SVG/DXF.
- Добавлены инструменты: труба (ломаная), ответвление с явной привязкой к существующей трубе, подпись, условное обозначение (кран, счётчик, регулятор, потребитель, стояк, фильтр), размер.
- Соединения создаются только при явной привязке начала/конца нового участка к существующей линии. Геометрическое пересечение без такой привязки само по себе не создаёт узел.
- Добавлены выбор элементов, перетаскивание вершин/символов/подписей, совместное перемещение вершин узла соединения, отмена/повтор действий и автосохранение.
- Добавлен экспорт чистового A4 SVG и DXF с отдельными слоями `PIPE_MAIN`, `JUNCTIONS`, `SYMBOLS`, `TEXT`, `DIMENSIONS` и `TITLE_BLOCK`. В экспорте используются только построенные в редакторе векторные объекты.
- Добавлены четыре теста ядра ручного CAD: нормализация геометрии, явная топология, SVG и DXF.

## Ограничения первой версии Manual CAD
- Это ручная векторизация подложки, а не автоматическое превращение фотографии в точную схему. Оператор сам ставит повороты, ответвления, символы, размеры и подписи.
- Экспорт сейчас использует встроенный A4-штамп и упрощённые условные обозначения. Точное копирование каждого поля/пиктограммы конкретного эталонного LPGCad-листа и автоматический перенос OCR-подписей сюда пока не входят.
- PDF и импорт DXF-шаблона в этот редактор не реализованы. SVG/DXF нуждаются в инженерной проверке.

## Граница изменений
- Не изменялись файлы `vdgo/`, VDGO backend/frontend, VDGO database, VDGO compose services, их порты, тома или конфигурация.
- Не изменялись `compose.yaml` и `nginx-unified.conf`; редактор работает как отдельная страница и API основного приложения.

## Проверки
- JavaScript syntax checks — успешно.
- 4 новых Node tests Manual CAD — успешно.
- Полный `npm run check` — успешно, включая существующие 121 Python-тест.

# ScadaProfit 4.3.19

- Исправлено слишком агрессивное автоматическое вращение: OSD должен пройти два независимых порога — ориентации (по умолчанию 8.0) и распознавания письменности (по умолчанию 2.0). При слабых показателях исходная ориентация сохраняется.

- Для каждой OCR-плитки сохраняются примеры исходных bbox, выходящих за границы, количество некорректных bbox и отсутствующих confidence.
- Геометрический алгоритм и критерии инженерного допуска не ослаблялись. Эта версия повышает наблюдаемость и предотвращает слабое автоповоротное решение, но сама по себе не исправляет разрывы трубопроводов.

# Изменения 4.3.18

## Геометрия и компоновка листа
- Чистовая компоновка перешла на профиль A4 portrait, соответствующий приложенному примеру (648×918 px). Для растрового эталона считываются формат, размеры и ориентация; заполненный JPEG не вставляется как подложка, чтобы не дублировать линии и подписи.
- Геометрия переносится из исходной системы координат на всю страницу с сохранением пропорций. Автоматическое выпрямление и схлопывание близких координат в чистовом экспортёре отключено.
- Неподтверждённые трубные фрагменты сохраняются отдельно в `DETAIL_REVIEW`; в `PIPE_MAIN` попадают только primary-пути.
- В чистовой слой допускаются только primary числовые подписи. Непроверенные слова и сомнительные OCR-значения остаются в диагностическом графе.

## OCR, трассировка и безопасность экспорта
- Бюджет повторных попыток плитки по умолчанию — 0. Ошибочная плитка повторяется при следующем запуске, успешные OCR/PIPE плитки восстанавливаются из checkpoint. Это не позволяет первой медленной плитке расходовать десятки минут на экспоненциальные повторы.
- Построчный OCR рукописных блоков откладывается, пока не завершены все основные OCR-плитки. Qwen-трассировка труб по-прежнему не запускается по неполной карте OCR.
- Лимит задания увеличен до 90 минут для последовательного OCR 3×3 и PIPE 3×3 с резервом времени на построение и экспорт графа. Лимит остаётся настраиваемым через `PYTHON_JOB_TIMEOUT_MS`.
- Частичная геометрия помечается watermark в SVG/DXF; интерфейс блокирует SVG/DXF/PDF до окончания всех плиток, оставляя JSON для диагностики и кнопку продолжения.
- Статистика переименована: количество CAD-путей — это число геометрических кандидатов, а не подтверждённые трубопроводы. Завершение вычислительных этапов не снимает `needs_review` и не заменяет инженерную проверку.

## Шаблон
- Сервер прикладывает сохранённый JPEG к запуску Python через `--template` и фиксирует копию эталона в папке задания, чтобы повтор использовал тот же профиль.
- Эталон из текущей загрузки — заполненный скан, а не чистый бланк. Его размеры/ориентация используются как профиль страницы; точные легендарные пиктограммы, индивидуальные поля адреса и подписи пока не векторизуются автоматически.

## Проверки
- `npm run check` — успешно.
- JavaScript и Python syntax checks — успешно.
- Unit tests: **118 passed**.
- Проверены рендеры A4 portrait, сохранение координат, слой `DETAIL_REVIEW`, фильтрация numeric labels watermark неполного SVG/DXF и блокировка диагностики для незавершённого OCR.
- Реальный прогон Qwen/Ollama и Docker GPU на целевом сервере в этой среде не выполнялись.
