# ScadaProfit 4.5.10 — быстрый запуск и изменения

## Обновление

Распакуй архив поверх отдельной копии проекта, сохранив свои `.env` и резервную копию данных. Команды выполняй в корне, где расположен основной `compose.yaml`:

```bash
docker compose build --no-cache app vdgo-backend
docker compose up -d --no-deps --force-recreate app vdgo-backend
docker compose restart gateway
```

Не выполняй `docker compose down -v` и не удаляй постоянные тома: `cad_jobs`, `vdgo_postgres_data`, `vdgo_output`, `vdgo_uploads`.

## Что изменилось для приёмщика

1. «Команда» постоянно видна в левой панели основных модулей.
2. Схемы и фото дефектов находятся в одном списке уведомлений; используй фильтр по адресу, чтобы найти конкретный дом.
3. Для схемы: открой уведомление, просмотри CAD, прими схему, затем нажми **«Добавить схему в заключение»**.
4. Для дефектов: открой уведомление, просмотри фотографии, установи отметку **«Да, фотографии подходят»**, затем нажми **«Добавить фото дефектов в заключение»**.
5. Каждая операция привязана к одному конкретному заданию/дому. После перехода откроется форма заключения именно этого адреса.

## Как материалы попадают в документ

- Принятые схемы, явно добавленные приёмщиком, включаются в раздел актуальных схем (пункт 7 PDF и Word).
- Фото дефектов, явно добавленные приёмщиком, подставляются в стандартные фотополя формы и печатаются в Приложении 3 **«Фото дефектного участка»**. Если снимков больше, чем штатных слотов, генератор добавляет листы продолжения Приложения 3.
- В форме заключения вручную проверь фотографии и отметь обязательное подтверждение содержания.
- Если открыть `/conclusion.html` без параметра конкретного задания, форма остаётся самостоятельной: нет общей постоянной подборки готовых схем. Её можно заполнить вручную.

## Ручная проверка после обновления

1. Войти под приёмщиком и убедиться, что «Команда» постоянно есть слева без открытия «Настроек».
2. Открыть «Уведомления»: схемы и дефекты должны быть в общем списке, фильтр должен находить нужную улицу/дом.
3. Для тестового дома принять схему и отдельно добавить её в заключение; проверить, что она есть в пункте 7.
4. Для того же или другого тестового дома принять фото дефектов и отдельно добавить их в заключение; проверить приложение 3.
5. Сформировать PDF и DOCX, проверить подписи адреса и фото.
6. Открыть обычное «Заключение» из меню без задания и убедиться, что ручное заполнение доступно.

## Проверка версии

Основное приложение: `4.5.10`. VDGO backend: `5.3.9`. Если в health/diagnostics отображается другая версия, проверь, что пересобраны оба сервиса `app` и `vdgo-backend` из корневого Compose.
