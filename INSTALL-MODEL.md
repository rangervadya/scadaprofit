# Локальная Qwen3-VL для CAD-реконструкции

В версии 4.2.7 Qwen3-VL используется для двух отдельных задач:

1. **Семантическая трассировка:** модель должна вернуть осевые маршруты труб, точки поворотов и ответвления в JSON. Рукописные цифры, размеры, выноски, стрелки и символы не должны становиться трубопроводами. Эти маршруты используются как независимые подсказки на слое `QWEN_REVIEW`; основной `PIPE_MAIN` строится по отобранной геометрии OpenCV.
2. **OCR:** изображение делится на четыре перекрывающихся увеличенных фрагмента; модель возвращает текст и bbox. Распознанные подписи экспортируются как редактируемые CAD TEXT. Боксы средней уверенности также помогают исключить рукописные штрихи из линейных кандидатов.

Нужна Ollama 0.12.7 или новее и модель `qwen3-vl:4b` (более крупная модель может повысить качество, но требует больше ресурсов).

Для Docker Compose: загрузите модель один раз:

```bash
docker compose exec ollama ollama pull qwen3-vl:4b
docker compose restart app
```

Для Ollama на хосте используйте `compose.host-ollama.yaml`. При обычном локальном запуске Python по умолчанию обращается к `http://127.0.0.1:11434/api/chat`.

## Проверка перед анализом

Откройте `http://АДРЕС-СЕРВЕРА:3001/api/health`. В ответе теперь есть `ollama.reachable`, `ollama.modelInstalled`, фактический список установленных моделей и подсказка, что исправить.

Для Docker выполните из каталога проекта:

```bash
# Убедиться, что сервис Ollama запущен
docker compose up -d ollama

# Установить модель в том Ollama (обычно скачивается один раз)
docker compose exec ollama ollama pull qwen3-vl:4b

# Перезапустить обработчик после установки модели
docker compose restart app
```

Если Ollama установлена прямо на сервере, а не в Compose:

```bash
ollama list
ollama pull qwen3-vl:4b
curl http://127.0.0.1:11434/api/tags
```

Затем проверьте `compose.host-ollama.yaml` и адрес `OLLAMA_CHAT_URL`/`OLLAMA_TAGS_URL`.

## Настройки

- `QWEN_MODEL` — модель Ollama, по умолчанию `qwen3-vl:4b`.
- `QWEN_OCR_TILE_GRID=3` — сетка OCR (3×3 перекрывающихся фрагмента).
- `QWEN_OCR_UPSCALE=2.0` — увеличение фрагментов для чтения мелких цифр.
- `QWEN_OCR_TIMEOUT=40` — тайм-аут одного OCR-фрагмента в секундах.
- `QWEN_PIPE_TRACE_TIMEOUT=240` — тайм-аут дополнительной семантической трассировки для слоя `QWEN_REVIEW` в секундах.
- `QWEN_PIPE_MAX_IMAGE_EDGE=2048` — максимальная сторона изображения для задачи трассировки.
- `QWEN_PIPE_MIN_CONFIDENCE=35` — минимальная уверенность маршрута для основного листа. Если поле confidence отсутствует в ответе модели, используется 60% с меткой needs_review.

`GET /api/health` сообщает модель и наличие адреса Ollama. Если Ollama недоступна или маршруты не распознаны, `/api/health`, строка состояния и `graph.json → semanticTrace` показывают причину и действие. Отсутствующее поле `confidence` больше не обнуляет правильный маршрут: применяется пометка 60% и он остаётся на проверку. Поддерживаются как объекты маршрутов, так и обычные массивы координат. Приложение сохраняет геометрические кандидаты на замороженном слое `DETAIL_REVIEW`, но не выдаёт их за трубопроводы на основном листе. На лист выводится явное предупреждение.

Не удаляйте Docker volume `ollama_data` при обновлении: в нём хранятся скачанные модели.
