# JSON Brain — инструкция

## Что где отображается

- Слева сверху — загрузка фотографии и редактируемый промпт извлечения.
- Справа сверху — исходное фото и SVG-построение из JSON. Серые линии — входной JSON, оранжевые — кандидатный ответ Qwen.
- Слева снизу — editable JSON графа, START_ID, END_ID и большой промпт построения пути.
- Справа снизу — три вкладки: raw JSON с фото, raw JSON пути и независимая проверка.

## Правильный порядок теста

1. Выбери исходное фото.
2. Нажми «1. Извлечь линии (полилинии)».
3. Открой «1 · Raw JSON с фото». Это дословный `message.content` от Ollama. Не ориентируйся только на картинку или статус.
4. Сравни `points`/`lines` с исходником. Если массива нет или он пустой, ошибка уже на этапе image → graph.
5. Поправь JSON вручную, если хочешь отдельно протестировать следующий этап.
6. Укажи START_ID и END_ID. Если путь однозначен — нажми «2. Построить путь».
7. Открой «2 · Raw JSON пути» и «3 · Проверка». Сравни ответ Qwen с `localValidation.warnings`.

## Как читать результат

- `done_reason=length` — ответ мог быть обрезан лимитом токенов.
- `points=0, lines=0` на этапе фото — модель не извлекла геометрию.
- `status=ok`, но `localValidation.valid=false` — не доверяй `ok`; читай `localValidation.warnings`.
- `total_length` в ответе сравнивается с длиной, которую локально пересчитал сервер.
- Оранжевая линия визуализируется из координат и `from/to` raw-ответа Qwen; она не сглаживается и не перестраивается CAD-рендерером.

## Формат графа

```json
{
  "points": [
    {"id":"P1","x":199,"y":415},
    {"id":"P2","x":854,"y":217}
  ],
  "lines": [
    {"from":"P1","to":"P2"}
  ],
  "warnings": []
}
```

Холст 1000×650, начало координат — левый верхний угол. Направление ребра строго from → to. Близость точек не создаёт связь.

## Что изменено в 2.9.0 после диагностики Qwen

- Промпт фото→граф просит трассировать обычные синие/фиолетовые рукописные штрихи; для них не нужны CAD-символы, стрелки или маркеры.
- Нечитаемые подписи больше не причина отбрасывать геометрию. Если виден хотя бы один уверенный участок трассы, модель должна вернуть его, а сомнения перечислить отдельно.
- Сервер отправляет JSON Schema в поле `format` Ollama и ограничивает ответ до 3600 токенов. По документации Ollama `format` поддерживает JSON Schema; сама схема ограничивает формат, но не гарантирует правильность распознавания.
- Старый промпт из `localStorage` версии 2.7 больше не подменяет новый: используется отдельный ключ `jsonBrainVisionPrompt_v29`. После обновления стандартный промпт загрузится автоматически. Кнопка «Восстановить промпт» также удаляет старый ключ.
- Если `done_reason=length`, журнал теперь отличает незакрытый JSON от случая, когда объект JSON вообще не начинался.



## Изменение 2.9.0: photo → polylines

- Vision-модель больше не должна сразу решать инженерную топологию. Она возвращает `strokes`: независимые кандидатные полилинии с 2–10 координатами и `confidence`.
- Сервер строит цепочки графа из последовательных точек каждого stroke. Он не объединяет разные штрихи даже при совпадающих/близких координатах. Это сознательно сохраняет неопределённость соединений.
- Для проверки маршрута пользователь должен вручную подтвердить и при необходимости объединить ветви в редакторе JSON.
- `image_summary` — описание; `strokes` — фактические локализованные координаты. Одно без другого не считается распознанной геометрией.
