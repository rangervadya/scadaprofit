# ScadaProfit 4.3.45 — автотрасса по эскизу слесаря и единое меню ПРОФИТ


## 4.3.45 — помощник ручной трассировки

В CAD добавлен инструмент **«Автотрасса»** для переноса отдельной трубы с исходного эскиза. Оператор указывает начало, конец каждого прямого участка и промежуточные точки на поворотах. Поиск идёт по тёмным и синим пикселям ручки в ограниченном коридоре, поэтому предпросмотр нужно проверить перед нажатием «Применить маршрут». Начальные, конечные и промежуточные точки могут создавать явные соединения с ранее подтверждёнными CAD-трубами. Оранжевые review-кандидаты не используются для привязки и чистового экспорта.

Это не полностью автоматическое распознавание смысла рисунка: автотрасса повторяет выбранный оператором штрих. Инженер проверяет, что это именно трубопровод, и отдельно размечает ветви, символы и размеры. Подробная инструкция: `MANUAL-CAD-USER-GUIDE-RU.md`.


## Единая навигация

В основном приложении распознавания эскизов, CAD-редакторе и VDGO добавлено одинаковое адаптивное бургер-меню. Через него открываются три независимых модуля: `/` — распознавание эскизов, `/manual-cad.html` — CAD-редактор, `/vdgo/` — технические заключения ВДГО. Backend и хранилища модулей не объединяются.

Подробности 4.3.43 — в `CHANGELOG-4.3.43-RU.md`.


## Исправление 4.3.42: недопустимые координаты Qwen

Qwen PIPE теперь проверяет каждую точку относительно точной ширины и высоты изображения, отправленного в Ollama. Маршрут с координатами за пределами фрагмента отклоняется целиком; точки больше не обрезаются до границы исходной страницы. Это устраняет ложные граничные линии от ответов вроде `y=4800` для фрагмента высотой 480 px.

Подпись checkpoint изменена, поэтому старые сохранённые Qwen PIPE-ответы с прежней логикой проверки не переиспользуются. Диагностика показывает размеры фрагмента, диапазон неправильных координат и количество отклонённых маршрутов.

Дополнительно усилена защита ориентации: один лишь небольшой перевес OCR-оценки не может автоматически перевернуть технический чертёж на 180 градусов. По умолчанию для такого поворота требуется относительный перевес 35% (`OSD_FALLBACK_180_MIN_MARGIN`).


## Почему раньше получались каракули

Режим скелетизации строит центральные линии по всем тёмным пикселям листа. Он не знает, где труба, а где буква, цифра, размерная линия, стрелка, условный знак или шум скана. В 4.3.40 этот режим автоматически открывался первым и выглядел как готовый результат, хотя являлся только диагностической векторизацией исходных штрихов.

## Что изменено

- Результат теперь по умолчанию открывается в режиме **«Исходник»** — исходная фотография показывается без искажений.
- CAD-черновик выбирается автоматически только после прохождения проверок связности, пересечений, классификации символов и привязки размеров.
- При провале проверок интерфейс сообщает конкретные причины и не выдаёт сырые скелетные линии за готовую схему.
- Режим **«Все штрихи»** остаётся доступен для диагностики; режим **«Контуры штрихов»** также сохранён отдельно.
- Для неподтверждённого CAD-черновика отключён чистовой экспорт SVG/DXF/PDF. Исходное изображение можно распечатать в PDF; SVG/DXF в режиме исходника выключены, так как фотография не является векторной CAD-геометрией.
- Диагностика JSON содержит отдельный объект `cadReadiness` с причинами отказа от чистовой реконструкции.

## Проверки готовности

Учитываются доля открытых концов, плотность неоднозначных пересечений, классификация условных обозначений и привязка размеров к объектам. Для последнего запуска пользователя результат не готов: 384 открытых конца на 367 сегментов, 145 неоднозначных пересечений на 367 сегментов, классифицировано 0 из 8 символов, привязано 2 из 8 размеров. Поэтому чистовой CAD не должен автоматически показываться как готовый.

## Что не изменяется

Локальный Qwen через Ollama и Tesseract (`rus+eng`) остаются прежними. Не останавливаем и не перенастраиваем Ollama, Python/GPU-процесс другого приложения, VDGO, PostgreSQL, Nginx/gateway, Docker volumes, Compose и настоящий `.env`.

Обновление через GitHub:

```bash
git pull --ff-only
docker compose build app
docker compose up -d --no-deps app
```

Проверки:

```bash
npm run check
```

## Честное ограничение

Эта версия исправляет отображение и контроль готовности: сырая скелетизация больше не считается чистой схемой. Она пока не решает полностью распознавание всех труб, кранов, счётчиков, размеров, выносок и реальных соединений. Для этого требуется отдельное улучшение семантического распознавания и проверка специалистом.
