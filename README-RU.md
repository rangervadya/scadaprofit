## Исправления 4.2.6

- Отдельные лимиты генерации Ollama: OCR — 1024 токена, семантические трассы — 1536 токенов по умолчанию.
- Ограничен объём JSON-ответа для OCR и трассировки, чтобы модель не тратила несколько минут на лишний текст.
- OCR-тайм-аут по умолчанию увеличен до 180 секунд; семантический тайм-аут — 240 секунд.
- Трассировка труб больше не отправляет весь лист одним запросом: изображение делится на перекрывающиеся фрагменты 2×2, координаты возвращаются к общему листу, а каждый фрагмент экспортируется только внутри своей неперекрывающейся области.
- Для каждого запроса сохраняются диагностические метаданные ответа Ollama (`done_reason`, `eval_count`, JSON-ключи, число аннотаций/маршрутов), но не сохраняется сам текст распознанных надписей.

## Исправления 4.2.6

## Принцип работы
- Чистый CAD-лист теперь строится по семантическим осевым маршрутам труб, которые выделяет Qwen3-VL по перекрывающимся фрагментам 2×2, а не автоматически по всем сегментам LSD/Hough.
- Qwen получает отдельную задачу: пропускать цифры, подписи, размерные линии, выноски, стрелки, засечки и символы арматуры; возвращать только осевые линии труб, углы и реальные ответвления.
- Рукописный OCR выполняется на четырёх перекрывающихся увеличенных фрагментах изображения, чтобы мелкие размеры и цифры читались крупнее.
- OCR-боксы умеренной уверенности также маскируют штрихи символов от геометрического детектора, даже когда текст пока не подтверждён для экспорта. Продолжение трубы через такую область проверяется отдельно и сохраняется.
- Векторные кандидаты OpenCV остаются в графе и замороженном слое DXF `DETAIL_REVIEW`; они больше не подменяют семантические трубные маршруты в основном листе, когда Qwen их вернул.
- Если Ollama недоступен или Qwen не вернул маршруты, слой PIPE_MAIN остаётся пустым: пиксельные кандидаты доступны только для проверки на исходном оверлее и в замороженном слое DETAIL_REVIEW. Они не выдаются за трубопроводы.
- Увеличено упрощение полилиний для устранения мелкой дрожи рукописных штрихов.

## Исправления 4.2.2
- Чистый лист больше не экспортирует целые связные компоненты целиком: граф разбивается на непрерывные пути между узлами и терминалами.
- Короткие боковые штрихи символов, размерные риски и изолированные пометки не попадают на основной CAD-лист.
- Короткое продолжение трубы сохраняется, когда оно образует почти прямую сквозную трассу через узел.
- Все скрытые кандидаты сохраняются на слое DXF `DETAIL_REVIEW`, который заморожен при открытии; основные трассы вынесены на `PIPE_MAIN`.
- Добавлено мягкое упрощение ломаных Ramer–Douglas–Peucker для устранения мелкой дрожи пера без удаления реальных поворотов.
- Повторные границы одного толстого штриха от LSD/Hough объединяются; отдельные параллельные линии с белым промежутком не склеиваются.

## Исправления 4.2.1
- Уверенно распознанные надписи Qwen3-VL/Tesseract заменяются настоящими редактируемыми CAD TEXT, а не дублируются штрихами букв.
- Штрихи внутри подтверждённых OCR-рамок исключаются из линейной геометрии; непрерывная труба, проходящая через рамку, сохраняется.
- SVG и DXF оформляются как единый лист A3 с рамкой, полем чертежа, заголовком и основной надписью. DXF использует миллиметры и слои SHEET, PIPE_CANDIDATES, VERIFIED_TEXT и NOTES.
- Полилинии очищаются от лишних коллинеарных вершин; почти горизонтальные/вертикальные повороты аккуратно выравниваются без изменения диагональных ветвей.

## Как устроен движок

1. OpenCV нормализует освещение и формирует диагностическую маску чернил.
2. Qwen3-VL через Ollama определяет осевые маршруты труб с углами и ответвлениями; эти маршруты идут в основной CAD-лист.
3. Отдельный OCR-проход Qwen3-VL читает увеличенные фрагменты; Tesseract дополняет его. Надписи экспортируются как CAD TEXT, а найденные текстовые области исключаются из линейных кандидатов.
4. Концы сегментов объединяются в узлы только при расстоянии до 4,5 px.
5. Геометрические пересечения не становятся соединениями автоматически.
6. Короткие соосные разрывы перечисляются как предложения; пользователь подтверждает каждый.
7. Кандидаты можно показывать в диагностическом оверлее; они не попадают в основной слой автоматически. Узлы можно перемещать, а пользовательские соединения — добавлять вручную.
8. Текущий граф экспортируется в SVG, DXF и JSON; PDF получается через диалог печати браузера.

## Ограничения

Это экспериментальный, несертифицированный распознаватель. Qwen3-VL может пропускать ответвления, неточно ставить точки поворота или ошибаться в чтении цифр. OpenCV LSD/Hough всё ещё находит размерные линии, стрелки и части символов, но они хранятся отдельно как кандидаты для проверки. Если Qwen не вернул ни одного семантического маршрута, основной CAD-лист остаётся без трубных линий, а пиксельные кандидаты доступны только отдельно для проверки. Перед использованием в проектировании необходимо сверить топологию, все размеры и подписи с оригиналом.

## Локальный запуск

Требуются Node.js 20+, Python 3.11+, Ollama с моделью `qwen3-vl:4b`, Tesseract (`rus` и `eng`) и пакеты из `requirements.txt`. Без Ollama доступен только черновой геометрический режим; он не должен считаться полноценным CAD-распознаванием.

```bash
npm install
python3 -m pip install -r requirements.txt
npm start
```

Открой `http://localhost:3000`.

## Docker / Ubuntu

См. `UPDATE-RU.md`. По умолчанию приложение доступно на `http://SERVER-IP:3001`.
Для загрузки модели в локальный контейнер Ollama выполни один раз:

```bash
docker compose exec ollama ollama pull qwen3-vl:4b
```

При использовании Ollama, уже установленного на хосте, запускай Compose с `-f compose.yaml -f compose.host-ollama.yaml` и проверь `OLLAMA_CHAT_URL` в конфигурации.

При обновлении поверх `/opt/scadaprofit` сохраняй `.env` и именованный том Ollama. Не используй `docker compose down -v`.

## Файлы результата

- `graph.json` — кандидаты, узлы, пересечения, предложения соединений и OCR-аннотации.
- `overlay.png` — диагностическое наложение кандидатов на фотографию.
- `ink-mask.png` — исходная общая маска чернил. Подтверждённые текстовые штрихи фильтруются на этапе построения линейных кандидатов, а не изменением исходной маски.
- `clean.svg` / `drawing.dxf` — предварительный CAD-лист: семантические маршруты Qwen на `PIPE_MAIN`, кандидаты OpenCV на замороженном `DETAIL_REVIEW`, уверенные подписи на `VERIFIED_TEXT`.
