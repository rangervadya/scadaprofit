# ScadaProfit 4.3.16 — восстановление обработки Qwen по плиткам

## Что исправлено

- OCR и Qwen PIPE сохраняют результат каждой успешно обработанной плитки в атомарный checkpoint-файл.
- Пустой, но успешно обработанный ответ отличается от тайм-аута/ошибки.
- При повторном запуске используются checkpoint-файлы только для того же исходного подготовленного изображения, модели и набора параметров. Неудачные/отсутствующие плитки запрашиваются заново.
- Временные сетевые ошибки, тайм-ауты и HTTP 408/425/429/500/502/503/504 могут получить ограниченные повторные попытки. По умолчанию общий бюджет — 2 повтора на этап за один запуск; запросы остаются последовательными.
- Тайм-аут повтора плавно увеличивается (по умолчанию ×1,25; максимум 360 секунд). История попыток и длительности записываются в `graph.json` и `progress.log`.
- Если не обработаны все плитки OCR или PIPE, граф явно помечается `analysisStatus: incomplete`, а схема не получает статус `completed`. Частичный SVG/DXF остаётся только для просмотра/проверки.
- Кнопка «Повторить преобразование» в адресной библиотеке запускает то же задание; успешные плитки будут восстановлены, повторно запрашиваются только отсутствующие.
- При полном успехе очищается флаг частичного результата.

## Важное ограничение для первого повтора

Старые задания, начатые до установки 4.3.16, не имеют checkpoint-файлов, потому что предыдущая версия их не создавала. Первый запуск после обновления повторно обработает все плитки и создаст `.checkpoints`. Если он снова завершится частично, следующий запуск уже сможет пропустить успешные плитки.

Checkpoint-файлы находятся внутри папки конкретного задания:

`/data/cad-reconstruction-jobs/<job-id>/.checkpoints/`

Их не нужно создавать или редактировать вручную. Не удаляйте Docker-том `cad_jobs` и каталог заданий.

## Что не менялось

- Модель `qwen3-vl:4b-instruct`, Ollama и CUDA.
- Сетка 3×3 и разрешение исходного изображения.
- OCR/Tesseract и правила геометрической проверки труб.
- `compose.yaml`, настройки GPU, Nginx Gateway и другие контейнеры.

Эта версия повышает устойчивость и возможность продолжить задание после тайм-аутов. Она не гарантирует ускорение самой модели и не устраняет любую причину медленного инференса. Реальное время следует измерить на сервере.

## Загрузка через GitHub

Замените в репозитории только перечисленные пять файлов, сохранив пути, и сделайте Commit changes в ветку `main`.

## Обновление на сервере

```bash
cd /opt/scadaprofit

git pull --ff-only origin main

sudo docker compose config --quiet

sudo docker compose build app

sudo docker compose up -d --no-deps app

sudo docker compose ps

curl -sS http://127.0.0.1:3001/api/health
```

`--no-deps app` пересобирает и перезапускает только приложение; Ollama и остальные сервисы не перезапускаются.

## Проверка результата

В health API ожидается `version: 4.3.16`.

В интерфейсе адресной библиотеки открой неудачную схему и нажми «Повторить преобразование». В `progress.log` должны появляться сообщения `restored from checkpoint` для успешных плиток и `retrying attempt` для временных ошибок. В `graph.json` смотри:

- `complete`;
- `analysisStatus`;
- `incompleteReasons`;
- `ocr.qwen.tile_diagnostics`;
- `semanticTrace.tile_diagnostics`;
- `attempt_history` внутри диагностики запросов.

Только `complete: true` означает, что все объявленные плитки обоих Qwen-этапов завершились. Любой `incomplete` результат не следует использовать как окончательный чертёж.
