# ScadaProfit 4.5.8 — обновление, аккаунты и рабочий процесс

## 1. Обновление

В каталоге проекта:

```bash
docker compose build --no-cache app
docker compose up -d --no-deps --force-recreate app
docker compose restart gateway
```

Команды выполняются **из корневой папки проекта**, где лежит основной `compose.yaml`. В этой версии обновляется основной контейнер `app`, в котором находится командная панель и очередь дефектов. Контейнер `vdgo-backend` не менялся. Для раздела 7 PDF/Word остаётся установленный backend 5.3.8.

При первом развёртывании:

```bash
docker compose up -d --build
```

Не удаляй постоянный том `cad_jobs`: в нём хранятся аккаунты, задания, отчёты и CAD-проекты.

## 2. Вход и аккаунты

Каждый сотрудник входит только по персональному логину и паролю. Нельзя выбрать чужой аккаунт или роль вместо ввода пароля.

Руководитель создаёт аккаунт через вкладку «Создать аккаунты»: указывает имя и фамилию, выбирает роль «Слесарь» или «Приёмщик». Система выдаёт уникальный логин и случайный пароль.

Вкладка «База аккаунтов» показывает сотрудников, ФИО, роли и логины. Пароли хранятся в виде криптографических хешей, поэтому старый пароль нельзя прочитать из базы. Кнопка «Выдать новый пароль» заменяет старый случайным новым, завершает текущие сессии сотрудника и показывает новые данные для копирования.

## 3. Рабочий процесс слесаря

Руководитель назначает дату, улицу, дом, слесаря и инструкции.

Слесарь выполняет последовательность кнопками:

1. «Начать обход дома».
2. «Отметить: прошёл этот дом».
3. «Отметить: пришёл в офис».
4. Прикрепить изображение ручной схемы и отправить его на автоматическое преобразование в CAD.
5. В отдельной форме прикрепить до 10 фотографий дефектов подъезда и при необходимости описать подъезд, этаж и место дефекта.

Фотографии дефектов отправляются отдельной очередью приёмщику и не попадают в CAD/пункт 7 заключения. GPS не используется. Геолокация не запрашивается и не сохраняется. Руководитель видит только отметки кнопок и время событий.

## 4. Уведомление, CAD и заключение

После отправки ручного эскиза сервер ставит его в штатную очередь автоматической реконструкции. Схема привязывается к адресу. Приёмщик получает уведомление с улицей и домом, видит оригинальный эскиз и предпросмотр CAD.

Приёмщик может открыть CAD-редактор, показать или скрыть оригинал, исправить линии, узлы, подписи и сохранить чертёж. Кнопка «Добавить в заключение» доступна в уведомлении после готовности CAD, а также непосредственно в редакторе для схемы, полученной от слесаря.

После переноса в «Заключение» включается именно сохранённый CAD-проект приёмщика (включая ручные правки), а не только первоначальный автоматический предпросмотр. Там доступны предпросмотр и актуальный SVG/DXF.

Пункт «Заключение» и самостоятельная форма технического заключения сохранены. Её по-прежнему можно открыть и заполнить вручную — перенос схемы из уведомления не является обязательным.

## 5. Роли

- **Слесарь:** личные задания, кнопки этапов, отправка ручных эскизов в CAD и отдельных фотоотчётов о дефектах подъезда.
- **Приёмщик:** отдельные очереди уведомлений о схемах и дефектах; редактирование CAD, перенос схем в заключение, подтверждение фотографий дефектов галочкой «Да, фотографии подходят» или возврат на исправление.
- **Руководитель (до двух аккаунтов):** назначения, контроль отметок, создание аккаунтов слесарей и приёмщиков, база логинов и переиздание паролей.
- **Разработчик:** полный доступ к ролям, заданиям, отчётам, тестированию и настройкам.

## 6. Проверки

Запуск проверок:

```bash
npm run check
```

Для доступа через интернет настрой HTTPS и `COOKIE_SECURE=1` в `.env`. Полный Docker-запуск нужно проверить на целевом сервере, где доступен Docker и установлены внешние OCR/AI-зависимости.


## Исправление 4.5.3: отправка ручного эскиза

В версии 4.5.3 исправлено сохранение загруженной картинки, когда временная папка `/tmp` и постоянный том `/data` находятся на разных файловых системах. Для обновления достаточно пересобрать приложение и перезапустить gateway по командам выше. Том `cad_jobs` не удалять.


## Новое в 4.5.4: схемы из выездов в пункте 7 заключения

На странице «Заключение» в форме раздела «7. Актуальные схемы, удостоверения и акты» автоматически отображается список CAD-схем, добавленных приёмщиком из отчётов слесарей. Отметьте галочками только те адреса, которые относятся к формируемому заключению. Если вы открыли заключение по ссылке из конкретного уведомления (`?report=...`), соответствующая схема будет отмечена автоматически.

Перед созданием PDF или Word браузер подготавливает отмеченные CAD-предпросмотры и показывает статус «Готово». Пока подготовка не завершилась, кнопки формирования документов заблокированы. В итоговый PDF каждая выбранная схема добавляется отдельной страницей прямо в блоке пункта 7: с улицей, домом, ФИО слесаря и изображением актуального CAD-предпросмотра. При создании редактируемого Word эти же схемы вставляются как отдельные изображения, а адреса и подписи остаются текстом.

Неотмеченные схемы в документ не попадают и остаются в списке заключения. Ручные вложения в полях пункта 7 не заменяются и продолжают работать. Данные выбранных схем не включаются в JSON-файл сохранения формы.

При обновлении используйте:

```bash
docker compose build vdgo-backend app vdgo-frontend
docker compose up -d --no-deps vdgo-backend app vdgo-frontend
docker compose restart gateway
```

Постоянные тома `cad_jobs` и `vdgo_postgres_data` не удаляйте.


## Исправление 4.5.5: длинный список схем в пункте 7

Исправлена проверка длины: служебное поле `workforce_schemes_json`, которое содержит выбранные CAD-схемы в PNG/base64, больше не ограничивается общим лимитом 500 символов обычного текста. Сам JSON по-прежнему проходит отдельную проверку размера, формата и изображений. Обычные текстовые поля заключения сохраняют свои прежние ограничения.

Для установки обновления используйте команды:

```bash
docker compose build vdgo-backend app vdgo-frontend
docker compose up -d --no-deps vdgo-backend app vdgo-frontend
docker compose restart gateway
```


## Исправление 4.5.6: проверка служебного поля пункта 7 и версия backend

В 4.5.5 исключение для точного имени `workforce_schemes_json` уже было в исходнике, но ошибка указывала, что на сервере продолжает отвечать старая проверка. В 4.5.6 поле определяется с нормализацией регистра, крайних пробелов, суффикса `[]` и HTML-обёртки вида `form[...]`. После распознавания имя приводится к каноническому `workforce_schemes_json`.

В health endpoint добавлены `release=4.5.6` и `backendVersion=5.3.8`, а Docker-образ backend получил новый тег, чтобы можно было проверить фактически работающий контейнер.


## Фотоотчёты дефектов подъездов

После отметки «Пришёл в офис» у слесаря доступны две независимые формы: отправка ручного эскиза для CAD и отправка фотографий дефектов. В одном фотоотчёте допускается до 10 изображений JPEG/PNG/WEBP/TIFF/HEIC/HEIF размером до 16 МБ каждое и комментарий до 1200 символов. Фотоотчёт не запускает CAD-реконструкцию и не включается в пункт 7 заключения.

В меню приёмщика добавлена отдельная вкладка «Дефекты подъездов». Приёмщик открывает уведомление, видит улицу, дом, ФИО слесаря, комментарий и фотографии, затем ставит галочку «Да, фотографии подходят». Отметка сохраняется на сервере и становится видна слесарю в истории его задания. При необходимости приёмщик может вернуть фотоотчёт на исправление с комментарием.

Фотографии хранятся в приватной папке отчётов; доступ выдаётся только вошедшим сотрудникам. Слесарь может просматривать файлы только собственных отчётов. Фотоотчёты не меняют статус CAD-схемы и не попадают автоматически в заключение.


В предпросмотре браузера JPEG/PNG/WEBP показываются как изображения. HEIC/HEIF/TIFF доступны ссылкой на оригинальный файл, если браузер не умеет встроенно отображать этот формат.


## Новое в 4.5.9: распределение нескольких домов приёмщиком

В кабинете приёмщика доступна вкладка «План работ». Выбери дату, активного слесаря, улицу, укажи дома по одному на строку (до 100 за раз) и назначь выезд. Для каждого дома будет создано независимое задание, объединённое группой назначения. Это позволяет слесарю отдельно отметить прохождение каждого дома и отправить схему/фото дефекта по правильному адресу.

В «Моих заданиях» слесарь видит дома, сгруппированные по дате: «Сегодня», «Завтра», остальные будущие даты и просроченные задания. В расписании приёмщика сгруппированные адреса отображаются одним блоком, при этом статус каждого дома ведётся отдельно. Старые одиночные назначения совместимы.

Для обновления:

```bash
docker compose build --no-cache app
docker compose up -d --no-deps --force-recreate app
docker compose restart gateway
```

Не удаляй постоянный том `cad_jobs`.
