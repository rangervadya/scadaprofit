# CAD Sketch JSON Brain 2.9.0

**В этой сборке оставлена только лаборатория Qwen JSON.** Старый путь обработки `OpenCV → skeleton → CAD-renderer`, локальный CAD-экспорт и `/api/convert` удалены из проекта. Приложение не строит автономный DXF и не перерисовывает картинку. Оно позволяет увидеть, что именно Qwen вернул, сравнить это с JSON-графом и проверить построение маршрута.

## Два независимых этапа

1. **Фото → граф:** `POST /api/qwen-extract`. На вход подаётся JPG/PNG/WEBP и vision-промпт. Qwen возвращает независимые `strokes` — кандидатные полилинии с координатами и confidence. Сервер детерминированно преобразует каждый stroke в цепочку соседних точек/рёбер. Разные штрихи и пересечения не объединяются автоматически. В ответе хранятся rawContent, parsed strokes, derived graph, parseError и метрики генерации.
2. **Граф → маршрут:** `POST /api/qwen-route`. Входной JSON `strokes`, START_ID, END_ID и редактируемый большой промпт отправляются Qwen. В ответе также есть rawContent и независимый `localValidation`.

Справа граф рисуется браузером непосредственно из координат JSON: серый — входные связи, оранжевый — ответ Qwen. Кнопки «Предыдущий/Следующий» подсвечивают один сегмент за раз. Когда ответ не прошёл независимую проверку, он всё равно отображается как кандидат, но отмечается предупреждением — он не выдаётся за достоверный маршрут.

## Важно про логи, которые были в 2.6.0

В 2.6.0 пользователь получил:

- `QWEN-EXTRACT points=0 lines=0`: модель вернула валидный/разбираемый объект, но пустой граф. Значит, это проблема этапа распознавания изображения, а не SVG-визуализатора.
- `QWEN-ROUTE status=ok ... localValid=false`: модель присвоила себе `ok`, но независимый валидатор обнаружил несоответствие. В 2.9.0 журнал дополнительно печатает `validationWarnings`, `modelLength`, `computedLength` и начало rawContent.

## Требования

- Docker Engine + Docker Compose plugin.
- NVIDIA Container Toolkit для использования GTX 1060 в Ollama (CPU тоже возможен, но будет медленнее).
- По умолчанию Ollama модель `qwen3-vl:4b-instruct`.
- Веб-интерфейс на `http://SERVER_IP:3001`.

## Переменные

Файл `.env`:

```env
WEB_PORT=3001
QWEN_MODEL=qwen3-vl:4b-instruct
```

## API

- `GET /api/health` — версия приложения, доступность Ollama и модели.
- `GET /api/prompts` — стандартные vision- и route-промпты.
- `POST /api/qwen-extract` — multipart `image`, optional `prompt`.
- `POST /api/qwen-route` — JSON `inputJson`, `startId`, `endId`, `prompt`.

В `server.js` намеренно нет старого `/api/convert`; в Dockerfile нет Python/OpenCV/Tesseract и CAD-пакетов.

## Независимая проверка

`graph.js` проверяет уникальность id, координаты в диапазоне 1000×650, наличие концов рёбер, самосвязи, дубли, направление, точное совпадение координат с входом, последовательность path/lines и длину. `total_length` сравнивается с независимым расчётом с допуском `1e-6`. Валидатор не исправляет ответ модели молча.

## Ограничение

Маленькая vision-модель может не распознать сложную рукописную схему и вернуть пустые массивы. Это не считается успешной реконструкцией. Для таких случаев просматривай rawContent, корректируй промпт и/или вручную поправляй входной JSON до проверки маршрута. JSON-лаборатория помогает локализовать ошибку, но не гарантирует автоматического инженерного распознавания.
