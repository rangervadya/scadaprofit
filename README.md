# Two Mask Lab 3.2.0 — сглаженные маски и векторная осевая линия

Офлайн-лаборатория OpenCV + Tesseract для экспериментов с рукописными схемами. Qwen/Ollama не вызываются.

## Что нового в 3.2

- Исходные бинарные PNG-маски остаются точными и неизменными. Для интерфейса создаются отдельные сглаженные превью с повышенным разрешением 2–4× (Lanczos).
- Добавлена векторизация маски линий: Zhang–Suen skeletonization, трассировка ветвей и независимых путей, упрощение полилиний RDP и мягкое сглаживание только небольших изгибов.
- SVG экспортируется с прозрачным фоном и тёмными линиями — без растрового прямоугольника и без объединения близких штрихов.
- Добавлены параметры preview scale, допуска упрощения, сглаживания, защиты углов, толщины SVG и минимальной длины пути. Эти настройки не запускают OCR повторно и не изменяют бинарные маски.
- В интерфейсе добавлено отдельное окно «Сглаженная векторная линия» и загрузка SVG.

## Что нового в 3.1

- Быстрые пресеты: «Баланс», «Больше текста», «Беречь линии», «Строгий OCR».
- OCR: уверенность 0–95 с шагом 1, увеличение 1–3×, языки `eng+rus` / `eng` / `rus`, режимы Tesseract PSM 3/4/6/7/8/11/12/13.
- Предобработка OCR: исходное серое изображение, изолированные чернила на белом, CLAHE, Otsu и adaptive threshold.
- Рамки OCR: отдельные абсолютные отступы 0–24 px и пропорциональное расширение 0–100%. При 0 px и 0% геометрическое расширение действительно нулевое.
- Фильтрация слишком маленьких OCR-боксов по ширине/высоте.
- Цвет чернил: авто, синий (диапазон H регулируется), фиолетовый, чёрный/карандаш, любые цветные чернила.
- Дополнительные фильтры насыщенности, яркости, допуска оттенка и удаления одиночных пикселей.
- Все применённые настройки сохраняются в JSON-отчёте.

## Что означают основные настройки

### Быстрые пресеты

- **Баланс**: confidence 35, 2×, PSM 11, серое исходное изображение. Начальный режим для ручки и смешанных пометок.
- **Больше текста**: confidence 15, 3×, чуть большие рамки. Захватывает больше подписей, но повышает риск включить фрагменты труб в текстовую маску.
- **Беречь линии**: confidence 65, нулевые отступы, большие минимальные OCR-боксы. Большая часть чернил остаётся в маске линий.
- **Строгий OCR**: confidence 55, 2.5×, CLAHE. Меньше кандидатов, часто меньше ложных областей, но рукописный текст может пропасть.

### Минимальная уверенность OCR

Увеличение порога оставляет меньше распознанных слов и, соответственно, меньше пикселей перемещает из маски линий в текст. Низкий порог включает слабые кандидаты, но OCR может принять случайные штрихи за буквы.

### Масштаб OCR

Изображение только для Tesseract увеличивается в 1–3 раза. Координаты найденных OCR-областей автоматически пересчитываются обратно к исходному размеру. Маски остаются в исходном разрешении.

### Предобработка

- **Исходное серое изображение** — лучший старт, если бумага и чернила различимы.
- **Только чернила на белом** — Tesseract видит только пиксели, найденные цветовым фильтром. Может отсечь фон, но тонкие символы распадаются.
- **CLAHE** — локально усиливает контраст, полезно при неравномерном освещении.
- **Otsu** — глобальная бинаризация; может усилить тени и текстуру бумаги.
- **Adaptive** — локальная бинаризация; полезна при тенях, но также способна принять фон за текст.

### PSM

- `11`: разрозненные подписи в разных местах — стартовый вариант для схем.
- `12`: разрозненный текст с анализом ориентации.
- `6`: один цельный блок.
- `3`: автоматическая сегментация страницы.
- `7` / `8` / `13`: строка или одно слово; обычно пригодны для экспериментов с отдельными зонами, а не всей схемой.

### Сглаживание и SVG

- **Масштаб сглаженного просмотра** (2–4×) влияет только на дополнительные изображения для экрана. Он не меняет исходное изображение, OCR, координаты OCR-боксов или бинарные маски.
- **Упрощение траектории** (0–3 px) удаляет мелкие пиксельные колебания при построении SVG. Слишком большое значение может срезать небольшие детали.
- **Сглаживание** (0–100%) округляет только небольшие изменения направления. Сильные повороты остаются углами.
- **Защита углов** (0–100%) повышает порог сохранения углов. Для трубопроводных схем оставляй это значение высоким.
- **Толщина SVG-линии** меняет только толщину отображаемого вектора.
- **Минимальная длина штриха** отбрасывает короткие фрагменты только из SVG, не из исходной маски.

Важно: SVG является приближённой центральной линией остаточной маски линий. Нераспознанные надписи и символы, оставшиеся в маске линий, тоже могут попасть в SVG. Векторизация не понимает смысл трубы и не создаёт инженерную топологию.

### Цветовые фильтры

- `blue`: регулируемые границы оттенка H, насыщенность и яркость.
- `auto`: находит доминирующий цвет и применяет регулируемый допуск ±.
- `purple`: фиксированный широкий фиолетовый диапазон.
- `dark`: порог яркости серого для чёрной ручки/карандаша.
- `anycolor`: все достаточно насыщенные цветные пиксели плюс тёмные нейтральные.

## Установка / обновление существующего `/opt/scadaprofit`

На Mac:

```bash
scp ~/Downloads/cad-sketch-converter-two-mask-3.2.zip tech@192.168.1.99:/home/tech/
```

На Ubuntu:

```bash
cd /opt/scadaprofit
tar -czf /root/scadaprofit-backup-$(date +%F-%H%M).tar.gz .
rm -rf /tmp/cad-two-mask-3.2
mkdir -p /tmp/cad-two-mask-3.2
unzip -oq /home/tech/cad-sketch-converter-two-mask-3.2.zip -d /tmp/cad-two-mask-3.2
cp -a /tmp/cad-two-mask-3.2/cad-sketch-converter-two-mask-3.2/. /opt/scadaprofit/
cd /opt/scadaprofit
docker compose config --quiet
docker compose build --no-cache app
docker compose up -d --force-recreate app
```

Не выполнять `docker compose down -v`. Обновляется только `app`, существующий Ollama-контейнер и его volume не затрагиваются. `.env` не включён в ZIP и остаётся на месте.

Проверка:

```bash
docker compose exec app node -p "require('./package.json').version"
curl -s http://127.0.0.1:3001/api/health | python3 -m json.tool
```

Ожидается `3.2.0`, режим `two-mask-lab-smooth-vector`.

## Текущий тестовый пример

На тестовом изображении 1280×906 (синий режим, H=90–145, saturation min=18, min brightness=20, PSM 11, `eng+rus`, исходное серое изображение, upscale 2×) один запуск OCR дал 111 сырых слов-кандидатов. Фильтрация по confidence дала:

| Порог | OCR-боксов | Пиксели текста | Пиксели линий |
|---:|---:|---:|---:|
| 15 | 95 | 44.8% | 55.2% |
| 35 | 69 | 33.3% | 66.7% |
| 55 | 39 | 12.0% | 88.0% |

Это показывает влияние настройки, но **не является оценкой точности текста**: Tesseract может ошибочно распознавать чертёжные штрихи как буквы. Смотри маски и список кандидатов, прежде чем выбирать настройки для реальных схем.

## API

`POST /api/masks` — multipart `image` и поля `mode`, `minConfidence`, `padding`, `paddingRatio`, `ocrScale`, `psm`, `language`, `preprocess`, `minBoxWidth`, `minBoxHeight`, `hueMin`, `hueMax`, `hueTolerance`, `saturationMin`, `minBrightness`, `maxBrightness`, `darkThreshold`, `minComponentArea`.

Ответ включает PNG-маски (`inkPngBase64`, `textPngBase64`, `linesPngBase64`, `overlayPngBase64`), OCR boxes, настройки и статистику.
