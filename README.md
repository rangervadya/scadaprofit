# CAD Sketch Converter Offline 2.5.0

Локальный веб-инструмент для **векторной трассировки рукописных инженерных эскизов**. Основная геометрия извлекается непосредственно из пикселей исходного фото, а не генерируется языковой моделью.

## Что изменилось в 2.5.0

- Удалена зависимость CAD-геометрии от Qwen. Пустой ответ модели больше не может превратиться в фиктивный чертёж.
- OpenCV выделяет цветные штрихи ручки (в первую очередь синюю/фиолетовую) или использует адаптивный порог для монохромных изображений.
- Центральные линии штрихов извлекаются алгоритмом thinning (Zhang–Suen).
- Скелет пикселей превращается в граф; на пересечениях трассы продолжаются по наиболее прямому направлению. Ответвления остаются отдельными дорожками с общими пиксельными точками.
- Tesseract ищет текст независимо от геометрии. OCR-кандидаты отображаются отдельно и не подставляются как достоверные размеры.
- Экспортируются PNG, SVG и DXF со слоями `CENTERLINE_PRIMARY`, `DETAIL_TRACE` и `ANNOTATION_TRACE` (плюс лист и примечания). OCR-пересечения лишь эвристически приглушаются; штрихи остаются редактируемыми в DXF.
- Статус результата теперь честно указывает **«НУЖНА ПРОВЕРКА»**. Реальный масштаб, диаметры и семантическая связность труб не обещаются.

## Ограничения — прочитать до использования

Это **векторная трассировка штрихов**, а не автоматическое понимание инженерной схемы. Она сохраняет линии, нарисованные на фотографии, но может также включить выноски, цифры, рукописные символы и размерные засечки. Точки пересечения не классифицируются как соединения труб. Размер в миллиметрах не восстанавливается без известного масштаба или контрольного размера.

Используйте DXF как редактируемую основу для дальнейшей ручной доводки. Перед монтажом или расчётом инженер обязан сверить оригинал, соединения, диаметры и все размеры.

## Структура

- `server.js` — HTTP API, загрузка файлов, запуск Python-процессов и выдача артефактов.
- `processor.py` — выделение штрихов, thinning, построение графа центральных линий, OCR.
- `cad_renderer.py` — SVG/PNG/DXF на листе A3.
- `public/` — веб-интерфейс.
- `compose.yaml`, `Dockerfile` — Docker-развёртывание.

## Запуск на Ubuntu через Docker

1. Распакуйте архив в каталог проекта, например `/opt/scadaprofit`.
2. Скопируйте `.env.example` в `.env` (по умолчанию порт 3001).
3. Соберите и запустите:

```bash
cd /opt/scadaprofit
cp -n .env.example .env
docker compose config --quiet
docker compose up -d --build
```

Откройте `http://IP_СЕРВЕРА:3001`.

Векторизация не зависит от Ollama. В Compose сервис Ollama оставлен как необязательная совместимость с прежней установкой; `model-init` находится в профиле `ai-setup` и не скачивает модель при обычном запуске.

## Обновление существующего сервера

Сначала сделайте резервную копию и распакуйте файлы поверх проекта. Не удаляйте тома:

```bash
cd /opt/scadaprofit
tar -czf /root/scadaprofit-backup-$(date +%F-%H%M).tar.gz .
```

Затем распакуйте архив и выполните:

```bash
docker compose config --quiet
docker compose build --no-cache app
docker compose up -d --force-recreate app
```

**Не выполняйте `docker compose down -v`.** Это удалит named volumes, включая хранилище старых моделей Ollama.

## Зависимости Python

- OpenCV (системный пакет `python3-opencv`)
- NumPy (идёт как зависимость OpenCV)
- pytesseract
- Tesseract OCR с языками `rus` и `eng`
- ezdxf
- CairoSVG

## Локальная проверка

```bash
npm run check
python3 processor.py /path/to/sketch.jpg /tmp/cad-test 1
python3 cad_renderer.py /tmp/cad-test/vectors.json /tmp/cad-test
```

Выход: `/tmp/cad-test/cad-redraw.png`, `cad-redraw.svg`, `cad-redraw.dxf`.
