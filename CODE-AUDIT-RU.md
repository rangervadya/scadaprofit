# Разбор кода по присланным файлам

## Подтверждённые проблемы

1. Присланный `server.js` — старая версия схемы `symbols/routes`. В её `makeTilePrompt()` буквально сказано не определять топологию и выдавать линии независимо. При этом `from_node/to_node` разрешено делать произвольными. Такой контракт не позволяет собрать общую сеть соединений.
2. В присланном `cad_renderer.py` рассчитанный список `routes` после `merge_routes()` не используется при рисовании: цикл идёт по `spec.get('routes')`. Значит, сшивание маршрутов не влияет на результат. Сама `merge_routes()` также может терять ответвления, потому что превращает компонент графа в линейную цепочку.
3. В присланном `cad_renderer.py` фон исходного фото встраивается с прозрачностью 50%. Это мешает получить чистый CAD-лист. Кроме того, пустая подпись заменялась внутренним ID маршрута и рисовалась в кружке.
4. В присланном `processor.py` контурная векторизация `findContours(RETR_TREE)` обводит контуры толщины рукописных штрихов, а не осевые линии труб. Это пригодно как трассировка пикселей, но не восстанавливает смысловую топологию CAD. В режиме CAD результат строится из данных Qwen, не из этого контура.
5. В обеих старых функциях нормализации координаты молча ограничивались диапазоном 0..1000. Если модель выдала неверную систему координат, значения могли схлопнуться к краю листа вместо явного отклонения.

## Что изменено в версии 2.4

- Используется графовая схема `nodes` + `connections`, где соединение ссылается на существующие узлы.
- Промпт чётко определяет, что `points` — только промежуточные повороты, а концы берутся из узлов; общий физический узел должен повторно использовать один ID.
- Координаты в JSON Schema ограничены 0..1000; выбрасываются точки вне диапазона.
- Рендерер обрабатывает до 400 маршрутов вместо 32 и больше не наносит внутренние ID как подписи.
- Включён присланный пользователем `processor.py` с более плотной скользящей сеткой фрагментов.

## Ограничение

Structured JSON гарантирует формат ответа, но не правильность топологии. Модель Qwen2.5-VL-3B всё ещё может ошибиться; поэтому инженерная проверка схемы обязательна.
